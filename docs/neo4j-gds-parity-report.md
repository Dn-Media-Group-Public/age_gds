# age_gds vs. Neo4j GDS: remaining parameter & functionality gaps

**2026-08-20 update:** the broader structural gap "no `CALL ... YIELD`
support — every age_gds function is SQL-only, none are callable from inside
a Cypher `cypher()` block" is now closed by
[Plan: Cypher-Callable Interface](implemented-plans/cypher-callable-interface.md):
every function gains an `(agtype, agtype)` overload usable as
`UNWIND age_gds.<name>(graphName, config) AS row` (AGE's Cypher grammar has
no `CALL ... YIELD`, so `UNWIND` stands in for it). This is a calling-
convention gap, not a parameter/config gap, so it doesn't remove any bullets
below on its own — but see the `bfs_stream` entry in §3, whose long-standing
result-shape mismatch is closed specifically via this new entry point.

Originally generated by directly fetching `https://neo4j.com/docs/graph-data-science/current/algorithms/*`
with a real Chrome user agent via Playwright (the site 403s generic HTTP
clients/WebFetch), and diffing the documented config parameters and result
columns against `docs/api.md` (since replaced by `docs/reference/`).

**2026-08-19 update:** `docs/implemented-plans/00-weight-plumbing.md` through
`docs/implemented-plans/06-new-graph-procedures.md` have since closed every
gap below that was tagged ✅ or ⚠️-closable-with-caveats and didn't require a
new external dependency — those bullets, and any function/section whose gaps
were fully closed, have been removed from this report. What remains below is
either:
- a genuine NetworKit API gap discovered or confirmed while implementing
  those plans (now a documented **permanent limitation**, not a to-do —
  age_gds refuses to hand-roll the missing algorithm or paper over undefined
  behavior, per project rules), or
- a gap that still needs one of the external libraries evaluated in
  `docs/neo4j-gds-parity-external-libs.md` (none of which have actually been
  added to the build yet — `CMakeLists.txt` links only NetworKit and OpenMP).

Every bullet: **what we have** → **what Neo4j GDS has** → **gap**.

> **NetworKit parity annotations:** every remaining gap below has been
> checked against the actual NetworKit headers in
> `third_party/networkit/include/networkit`. Each gap is tagged:
> - ❌ **Not in NetworKit** — no NetworKit class covers this; needs either an
>   external library or must stay a documented limitation.
> - 📦 **Would be closed by an adopted external library** — NetworKit has no
>   primitive for this, but one of the four libraries evaluated below would
>   close it. Not yet implemented — adopting the dependency is still an open
>   decision, not just a wrapper.

> **Decision (2026-08-18, not yet implemented): adopt a 4-library minimal
> set** to close the highest-value ❌ gaps at the lowest dependency/license
> cost, per `docs/neo4j-gds-parity-external-libs.md`. All four are header-only
> (or a small self-contained source drop), permissively licensed, and would
> combine into `age_gds.so` without imposing any copyleft obligation on the
> project (verified against age_gds's own `LICENSE` and NetworKit's MIT
> license). **None of the four have been added to `CMakeLists.txt` yet** —
> plans 0–6 only closed gaps that NetworKit itself could cover:
>
> | Library | License | Would close |
> |---|---|---|
> | **[Eigen](https://eigen.tuxfamily.org/)** (sparse module) | MPL 2.0, header-only | §1 `hits_stream` (real Kleinberg HITS via power iteration on AᵀA/AAᵀ) + §6 new `fastRP_stream` (FastRP via sparse random-projection matmuls) |
> | **[Boost Graph Library](https://www.boost.org/doc/libs/release/libs/graph/doc/graph_coloring.html)** | Boost Software License 1.0, header-only | §7 new `k1Coloring_stream` (`boost::sequential_vertex_coloring`) |
> | **[hnswlib](https://github.com/nmslib/hnswlib)** | Apache-2.0, header-only | §4 `knn_stream` (true property-vector KNN, closing the conceptual mismatch flagged there) |
> | **[pcst_fast](https://github.com/fraenkel-lab/pcst_fast)** | MIT, small self-contained source (no deps) | §7 new `prizeSteinerTree_stream` |
>
> Gaps **not** closed by this set even if adopted (no library met the
> low-dependency/permissive-license bar): delta-stepping, plain (non-prize-collecting)
> Steiner tree, min-weight k-spanning-tree, K-Means/HDBSCAN, SLLPA, approximate
> max-k-cut, CELF. These remain documented limitations; see
> `docs/neo4j-gds-parity-external-libs.md` for why each was excluded.

## 1. Centrality

### `pageRank_stream` / `pageRank_stats` / `pageRank_write`

Neo4j `gds.pageRank.stream(graphName, configuration)` still has two gaps
age_gds cannot close:
- `sourceNodes` `Node/Number or List or List of pairs as lists`, default `[]`
  — **missing** (personalized/biased PageRank; pairs form lets each source
  carry its own teleport bias).
- `maxIterations` — **have as a hardcoded internal cap of 20, not exposed as
  a parameter.**

> **NetworKit parity (permanent limitation):** `NetworKit::PageRank(G, damp,
> tol, normalized, SinkHandling)` (`centrality/PageRank.hpp`) has no public
> setter for `maxIterations` — it's a private member hardcoded internally,
> not exposed via constructor or setter. Exposing a per-call override would
> require patching the vendored NetworKit itself, not a wrapper, so this
> stays unsupported. `sourceNodes` (personalized/biased PageRank, teleport
> vector) is ❌ not in NetworKit at all — its `PageRank` class always uses a
> uniform teleport distribution with no way to bias it toward a source set.
> (`relationshipWeightProperty` and `scaler` were closed by
> [Plan: Centrality Algorithm Parity Fixes](implemented-plans/01-centrality-parity.md).)

### `eigenvector_stream`

Neo4j `gds.eigenvector.stream` still has two gaps:
- `maxIterations` Integer, default `20` — **missing** (not exposed; see
  PageRank above, same underlying NetworKit limitation).
- `sourceNodes` `List or Node or Number`, default `[]` — **missing**
  (personalized eigenvector centrality).

> **NetworKit parity (permanent limitation):** `NetworKit::EigenvectorCentrality(G, tol)`
> (`centrality/EigenvectorCentrality.hpp`) has no `maxIterations` constructor
> param or setter — same NetworKit-side gap as PageRank, not a wrapper
> problem. `sourceNodes` ❌ not in NetworKit — same limitation as PageRank's
> `sourceNodes`, no biasing mechanism exists. (`tolerance`,
> `relationshipWeightProperty`, and `scaler` were closed by
> [Plan: Centrality Algorithm Parity Fixes](implemented-plans/01-centrality-parity.md).)

### `hits_stream`

Neo4j `gds.hits.stream`:
- `hitsIterations` Integer, default `20` — **missing param, and missing the
  algorithm itself.**
- **Fidelity gap, not just params:** Neo4j's HITS is genuine Kleinberg HITS
  (distinct auth/hub via power iteration on `AᵀA`/`AAᵀ`). Ours returns the
  same `NetworKit::EigenvectorCentrality` score for both `auth` and `hub`
  columns — a documented substitution, not real HITS.

> **NetworKit parity:** ❌ Not in NetworKit. No `HITS`/`Hits`/`Hub`/`Authority`
> class anywhere under `third_party/networkit/include/networkit`.
>
> 📦 **Would be closed by adopting Eigen** (sparse module, MPL2, header-only,
> not yet added — see decision box above). Build the sparse adjacency matrix
> `A` from the NetworKit `Graph`, then run power iteration on `AᵀA`
> (authority) and `AAᵀ` (hub) using Eigen's sparse matrix-vector product —
> real, distinct Kleinberg auth/hub scores, closing both the `hitsIterations`
> gap and the fidelity gap in one fix.

### `articleRank_stream`

Neo4j `gds.articleRank.stream` config, remaining gaps:
- `maxIterations` Integer, default `20` — **have (as constant, fixed at
  20), missing as parameter** — same underlying `PageRank`-class limitation
  as `pageRank_stream`.
- `sourceNodes` `Node/Number or List or List of pairs as lists`, default `[]`
  — **missing** (same as PageRank's `sourceNodes`).

> **NetworKit parity (permanent limitation):** same underlying
> `NetworKit::PageRank` class and the same two gaps as `pageRank_stream`
> above — no `maxIterations` setter, no source-biasing mechanism.
> (`dampingFactor`, `tolerance` (now correctly defaulting to `1e-7`),
> `relationshipWeightProperty`, and `scaler` were closed by
> [Plan: Centrality Algorithm Parity Fixes](implemented-plans/01-centrality-parity.md).)

## 2. Community detection

### `louvain_stream`

Neo4j `gds.louvain.stream` config, remaining gaps:
- `seedProperty` String, default `n/a` — **missing** (no seeding support).
- `maxLevels` Integer, default `10` — **approximated, not an exact port:**
  age_gds exposes `recurse boolean` (multilevel on/off) instead of an
  integer level cap.
- `tolerance` Float, default `0.0001` — **missing** (not exposed by the
  backing NetworKit class).
- `includeIntermediateCommunities` Boolean, default `false` — **missing.**

> **NetworKit parity (permanent limitations):** `NetworKit::PLM(G, refine,
> gamma, par, maxIter, turbo, recurse)` (`community/PLM.hpp`) has no
> "start from an existing partition" constructor (unlike `PLP`, see Label
> Propagation below), so `seedProperty` ❌ is not supported. `maxLevels` has
> no direct numeric equivalent — PLM only offers the boolean `recurse`
> (multilevel on/off), which age_gds now exposes as the closest
> approximation (see `docs/architecture.md`); this is a permanent, documented
> approximation, not a to-do. `tolerance` ❌ is not exposed by PLM (no
> convergence-tolerance constructor param). `includeIntermediateCommunities`
> ❌ — PLM's coarsening levels are internal to `run()`; the public API only
> returns the final `Partition`, no per-level history.
> (`relationshipWeightProperty`, `gamma`/`maxIterations`→`max_iterations`,
> `consecutiveIds`, and `minCommunitySize` were closed by
> [Plan: Community Detection Algorithm Parity Fixes](implemented-plans/02-community-detection-parity.md).)

### `leiden_stream`

Neo4j `gds.leiden.stream` config, remaining gaps:
- `maxLevels` Integer, default `10` — **approximated, not an exact port:**
  age_gds's `iterations` parameter (repeated full Leiden runs) is only a
  loose analogue — Neo4j's `maxLevels` controls coarsening *depth* within one
  run, a different knob entirely.
- `theta` Float, default `0.01` (randomness in refinement) — **missing.**
- `tolerance` Float, default `0.0001` — **missing.**
- `seedProperty` String, default `n/a` — **missing.**

> **NetworKit parity (permanent limitations):** `NetworKit::ParallelLeiden(G,
> iterations, randomize, gamma)` (`community/ParallelLeiden.hpp`) is a real
> Leiden implementation, but `theta` (refinement randomness) ❌ is not
> exposed — its `randomize` is a bool (randomize node order or not), not a
> continuous randomness knob. `tolerance` ❌ is not exposed at all.
> `seedProperty` ❌ — no "start from partition" constructor. `maxLevels`'s
> `iterations` approximation is a permanent, documented divergence (see
> `docs/architecture.md`), not a to-do. (`relationshipWeightProperty` and
> `gamma` were closed by
> [Plan: Community Detection Algorithm Parity Fixes](implemented-plans/02-community-detection-parity.md).)

### `labelPropagation_stream`

Neo4j `gds.labelPropagation.stream` config, remaining gaps — both are
**permanent limitations discovered while implementing plan 02**, not
to-dos:
- `nodeWeightProperty` String, default `null` — **not supported.**
  NetworKit's `Graph` has no node-weight concept at all (only edge weights),
  and no community-detection class accepts a node-weight parameter, so there
  is nothing to delegate to; implementing it by hand would mean hand-rolling
  tie-breaking logic, forbidden by project rules.
- `seedProperty` String, default `n/a` — **rejected with
  `ERRCODE_FEATURE_NOT_SUPPORTED`, not implemented.** `NetworKit::PLP`'s
  seeded constructor (`PLP(G, baseClustering, theta)`) never initializes its
  private `maxIterations` member (confirmed in the vendored
  `community/PLP.hpp`/`.cpp`), so `run()`'s loop condition reads an
  uninitialized value on that path — undefined behavior, not a real
  algorithm to delegate to, and there is no public setter to fix it
  post-construction. age_gds refuses to rely on the resulting UB or
  hand-roll seeded label propagation.

(`maxIterations`, `relationshipWeightProperty`, and `consecutiveIds` were
closed by
[Plan: Community Detection Algorithm Parity Fixes](implemented-plans/02-community-detection-parity.md).)

### `wcc_stream`

Neo4j `gds.wcc.stream` config, one remaining gap:
- `seedProperty` String, default `n/a` — **missing.**

> **NetworKit parity (permanent limitation):** WCC's underlying
> `ConnectedComponents`/`WeaklyConnectedComponents` classes have no "start
> from a partial labeling" constructor — not supported by NetworKit for this
> family (unlike PLP above). (`relationshipWeightProperty`, `threshold`, and
> `consecutiveIds` were closed by
> [Plan: Community Detection Algorithm Parity Fixes](implemented-plans/02-community-detection-parity.md).)

## 3. Path-finding

### `bfs_stream`

**Result shape — closed via the Cypher-callable entry point, not a shape
change on the SQL one.** The SQL `age_gds.bfs_stream(...)` keeps its
existing one-row-per-node/`distance` shape (a distinct, useful feature with
no removal planned). The Cypher-callable overload added by
[Plan: Cypher-Callable Interface](implemented-plans/cypher-callable-interface.md)
— `age_gds.bfs_stream(graphName agtype, config agtype)`, called via
`UNWIND ... AS row` — matches Neo4j's actual `sourceNode, nodeIds` single-row
shape (still without a `path` field; see that plan for why). `maxDepth` and
`targetNodes` were closed by
[Plan: Path-finding & Flow Algorithm Parity Fixes](implemented-plans/03-pathfinding-parity.md).

### `deltaStepping_stream`

**Substitution, unchanged:** still runs plain `NetworKit::Dijkstra`, not
delta-stepping. Neo4j `gds.allShortestPaths.delta.stream`'s `delta` Float
parameter remains **missing**, and structurally can't be added without an
actual delta-stepping implementation.

> **NetworKit parity:** ❌ Confirmed not in NetworKit — no `DeltaStepping`
> class exists anywhere in the tree (only plain `Dijkstra`,
> `BidirectionalDijkstra`, `AlgebraicBFS`). Stays a documented substitution;
> not prioritized for external-library research (low value — Dijkstra is
> already correct, delta-stepping is a parallel-performance optimization,
> not a different result).

## 4. Similarity

### `knn_stream`

Neo4j `gds.knn.stream` config, remaining gaps:
- `nodeProperties` `String or Map or List of Strings/Maps`, **required** —
  **conceptual mismatch, unaddressed:** Neo4j KNN computes similarity over
  **node property vectors** (numeric/embedding features), not graph
  topology. Ours still computes Jaccard over neighbor sets, making
  `knn_stream` effectively a differently-parameterized `nodeSimilarity_stream`
  rather than true KNN.
- `sampleRate` Float, default `0.5` — **missing.**
- `deltaThreshold` Float, default `0.001` — **missing.**
- `randomSeed` — **missing.**

Neo4j also has a separate `gds.knn.filtered.stream` (source/target node
filtering) age_gds has no equivalent of.

> **NetworKit parity:** `sampleRate`/`deltaThreshold`/`randomSeed` are
> parameters of Neo4j's approximate randomized KNN-join algorithm
> (NN-descent-style) — implementing genuine sampling/early-stopping behavior
> would itself be "an algorithm," conflicting with project rules if attempted
> from scratch; since our current similarity computation is exact, these
> three are ❌ not meaningfully portable without an external approximate-NN
> library. For Neo4j's *actual* semantics — KNN over **node property
> vectors** — NetworKit has ❌ no generic feature-vector nearest-neighbor
> class at all (checked `similarity`-adjacent headers under `linkprediction/`
> and `embedding/`; nothing resembling ANN/vector search). This is a
> genuinely different problem domain NetworKit doesn't cover.
>
> 📦 **Would be closed (the conceptual-mismatch part) by adopting hnswlib**
> (Apache-2.0, header-only, not yet added — see decision box above). Its HNSW
> index would give true nearest-neighbor search over node property vectors,
> closing the conceptual mismatch by adding a genuine property-vector KNN
> function alongside (not replacing) the existing topology-Jaccard one.
> `sampleRate`/`randomJoins`/`initialSampler`/`perturbationRate` (Neo4j's
> NN-descent-specific tuning knobs) would remain ❌ not portable even with
> hnswlib in place — HNSW's incremental-graph construction is a different
> approximate-NN strategy than NN-descent.
> (`topK`'s default and `similarityCutoff` were closed by
> [Plan: Similarity & Link-Prediction Parity Fixes](implemented-plans/04-similarity-linkprediction-parity.md).)

## 5. Link prediction

### `linkprediction_adamicAdar` / `commonNeighbors` / `preferentialAttachment` / `resourceAllocation`

One remaining gap, now a **permanent limitation discovered while
implementing plan 04**: Neo4j's `direction` parameter (`OUTGOING`/`INCOMING`/
`BOTH`, default `BOTH`) is only partially supported. `direction => 'BOTH'`
works; `'OUTGOING'`/`'INCOMING'` raise `ERRCODE_FEATURE_NOT_SUPPORTED`.

> **NetworKit parity (permanent limitation):**
> `NetworKit::LinkPredictor::run()` (`linkprediction/LinkPredictor.hpp`)
> unconditionally throws `std::invalid_argument` on any directed graph, and
> none of the four predictor classes (`AdamicAdarIndex`,
> `CommonNeighborsIndex`, `PreferentialAttachmentIndex`,
> `ResourceAllocationIndex`) offer a directed-aware alternative — there is no
> NetworKit class to delegate an `OUTGOING`/`INCOMING`-restricted score to,
> and hand-rolling directed neighbor-set arithmetic is forbidden by project
> rules. (The structural mismatch — Neo4j's per-pair scalar design vs. our
> `runAll()` streaming — and `relationshipQuery` were closed by adding
> single-pair scalar functions in
> [Plan: Similarity & Link-Prediction Parity Fixes](implemented-plans/04-similarity-linkprediction-parity.md);
> the `*_stream` all-pairs functions remain available alongside them.)

## 7. Whole algorithm/procedure families with no age_gds equivalent

The base graph-filter/concurrency parameters (`nodeLabels`,
`relationshipTypes`, `concurrency`, `jobId`, `logProgress`) are omitted below
since they're identical across every GDS procedure and already covered by
our own `graph_name`/`age_graph`/`node_query`/`edge_query` conventions.

Plans 0–6 added new NetworKit-backed functions for what were previously gaps
here: A* shortest path (`shortestPath_astar_stream`), minimum-cost maximum
flow (`minCostMaxFlow_stats`), longest path in a DAG (`longestPath_stream`),
topological sort (`topologicalSort_stream`), Filtered Node Similarity
(folded into `nodeSimilarity_stream`'s `bottom_k`/`bottom_n`/
`upper_degree_cutoff`/`source_node_filter`/`target_node_filter`/
`use_components`/`similarity_metric` parameters), the conductance metric
(`conductance_stats`), clique counting (`cliqueCounting_stats`), and bridges
(`bridges_stream`) — all removed from this section accordingly. What remains
below still has no NetworKit primitive to build on.

### FastRP (`gds.fastRP.stream`) — node embeddings

> **NetworKit parity:** ❌ Not in NetworKit. No `FastRP` class exists anywhere
> under `embedding/` (only `Node2Vec` and the generic `LearnEmbedding`
> skip-gram trainer).
>
> 📦 **Would be closed by adopting Eigen** (sparse module, MPL2, header-only,
> not yet added — see decision box above; same dependency as `hits_stream`).
> FastRP is a sparse random-projection matrix (Achlioptas-style) multiplied
> iteratively against the normalized adjacency matrix — Eigen's sparse
> matrix-vector product and random sparse matrix construction provide
> exactly these primitives.

### GraphSAGE (`gds.beta.graphSage.stream`) — inductive neural embedding

Requires a separately-trained model (`gds.beta.graphSage.train`).

> **NetworKit parity:** ❌ Confirmed — no neural-net / GraphSAGE class
> anywhere in the tree. Out of scope (would require both a GNN library and a
> model-catalog concept `age_gds` doesn't have — too large a scope expansion
> for this thin-glue-layer project); not delegated for external research.

### Yen's Shortest Path (`gds.shortestPath.yens.stream`) — k-shortest-paths

> **NetworKit parity:** ❌ Not in NetworKit. No k-shortest-paths /
> Yen's-algorithm class found anywhere under `distance/`. Low priority —
> k-shortest-paths is a fairly self-contained algorithm (repeated
> constrained Dijkstra calls) that a small library could cover cheaply.

### Minimum Weight k-Spanning Tree (`gds.beta.spanningTree.kmst.stream`)

> **NetworKit parity:** ❌ Not in NetworKit. No k-constrained /
> bounded-size spanning tree class exists — `RandomMaximumSpanningForest`
> (used for `spanningTree_stream`) builds a full spanning forest, not a
> k-edge-limited tree. Low priority (niche procedure).

### Minimum Directed Steiner Tree (`gds.steinerTree.stream`)

> **NetworKit parity:** ❌ Not in NetworKit. No `SteinerTree`/`SteinerForest`
> class anywhere in the tree (checked `graph/`, `distance/`, `community/`).
> Steiner tree is NP-hard and genuinely needs a dedicated approximation
> algorithm — not derivable from NetworKit's MST/Dijkstra primitives via a
> simple wrapper.

### Prize-Collecting Steiner Tree (`gds.beta.prizeSteinerTree.stream`)

> **NetworKit parity:** ❌ Same as plain Steiner tree above — not in
> NetworKit.
>
> 📦 **Would be closed by adopting `pcst_fast`** (MIT, small self-contained
> C++ source, no dependencies, not yet added — see decision box above).
> Dedicated implementation of the Goemans-Williamson prize-collecting Steiner
> forest scheme. The *plain* (non-prize-collecting) Steiner tree gap above
> remains open regardless — the only library found for that (OGDF) is
> GPL-2/3 and was excluded on licensing grounds.

### Filtered KNN (`gds.knn.filtered.stream`)

Same base config as `knn_stream` plus `maxIterations`, `randomJoins`,
`initialSampler`, `similarityCutoff`, `perturbationRate`,
`sourceNodeFilter`/`targetNodeFilter`, `seedTargetNodes` — age_gds has no
filtered-KNN function at all (plain `knn_stream`'s topology-Jaccard
substitution has no filter parameters either).

> **NetworKit parity:** same split as plain `knn_stream` above.
> `maxIterations`/`randomJoins`/`initialSampler`/`perturbationRate` are
> internals of Neo4j's NN-descent approximate-KNN algorithm, which NetworKit
> doesn't implement.
>
> 📦 **Would be partially closed by adopting hnswlib** (see `knn_stream`
> above and the decision box) — `sourceNodeFilter`/`targetNodeFilter`/
> `similarityCutoff` would become real filters over hnswlib's property-vector
> index. `maxIterations`/`randomJoins`/`initialSampler`/`perturbationRate`
> would remain ❌ not portable even with hnswlib in place — those are
> specifically NN-descent's tuning surface, and HNSW construction doesn't
> expose equivalent knobs.

### Speaker-Listener Label Propagation / SLLPA (`gds.sllpa.stream`) — overlapping community detection

> **NetworKit parity:** ❌ Not in NetworKit. No SLLPA / overlapping-community
> class exists — `community/` has `PLM`, `PLP`, `ParallelLeiden`,
> `LouvainMapEquation`, `LFM`, `CutClustering`, etc., all disjoint/hard
> partitioning; `OverlappingCommunityDetectionAlgorithm.hpp` exists as a
> *base class* but has no SLLPA subclass implementing it. Genuinely absent —
> overlapping community detection is a qualitatively different capability
> none of our current algorithms provide.

### K-1 Coloring (`gds.k1coloring.stream`)

> **NetworKit parity:** ❌ Not in NetworKit. Checked `randomization/`,
> `coloring.py` (Python-only, no corresponding C++ header), and grepped for
> "Coloring"/"Colouring" across all headers: nothing. Graph coloring is
> entirely absent from the C++ API.
>
> 📦 **Would be closed by adopting Boost Graph Library** (Boost Software
> License 1.0, header-only, not yet added — see decision box above).
> `boost::sequential_vertex_coloring` is a direct, well-tested, greedy
> vertex-coloring algorithm.

### K-Means Clustering (`gds.kmeans.stream`) — property-vector clustering

> **NetworKit parity:** ❌ Not in NetworKit — K-Means operates on
> `nodeProperty` feature vectors, not graph topology, a different domain than
> everything else in this codebase (similar to Neo4j's real KNN). No
> k-means/clustering-over-vectors class exists in NetworKit. Best candidate
> external libraries (mlpack/dlib) pull in more than this project's
> minimal-dependency bar wants — deferred.

### HDBSCAN (`gds.hdbscan.stream`)

> **NetworKit parity:** ❌ Not in NetworKit — same property-vector-clustering
> domain as K-Means above. Grouped with K-Means and property-vector-KNN under
> the "needs a vector-math library" bucket, deferred for the same reason.

### Approximate Maximum k-cut (`gds.approxMaxKCut.stream`)

> **NetworKit parity:** ❌ Not in NetworKit — checked for
> "kcut"/"KCut"/"MaxKCut" across the whole tree, nothing found. Approximate
> max-k-cut (local search / VNS) is a distinct combinatorial-optimization
> algorithm not covered by any existing NetworKit class (community-detection
> classes optimize modularity/resolution objectives, not cut-size
> objectives). Only viable external library found, OR-Tools, is too heavy a
> dependency for this feature — deferred.

### CELF (`gds.beta.influenceMaximization.celf.stream`) — influence maximization

> **NetworKit parity:** ❌ Not in NetworKit. No influence-maximization / CELF
> / independent-cascade class exists (checked `simulation/`, `scd/`,
> `dynamics/` — none implement the independent-cascade diffusion model CELF
> requires). No credible maintained external library found either —
> deferred.

## 8. External-library research for gaps NetworKit cannot cover

The items below have no NetworKit primitive to build on — closing them would
require a "never implement a graph algorithm from scratch" violation if done
in-house. See `docs/neo4j-gds-parity-external-libs.md` for the full research.
Plans 0–6 closed every gap NetworKit itself could cover; **none of these
external-library adoptions have been implemented** — the table below
reflects the 2026-08-18 decision (see the boxed note near the top of this
document), still pending execution:

1. **Real HITS** (`hits_stream`) — 📦 would be closed by Eigen (power
   iteration on AᵀA/AAᵀ); not yet implemented.
2. **Delta-stepping SSSP** (`deltaStepping_stream`) — open, deferred (low
   priority, Dijkstra is already correct, just not parallel).
3. **FastRP** — 📦 would be closed by Eigen (sparse random-projection
   matmuls); not yet implemented.
4. **Yen's k-shortest-paths** — open, deferred (low priority, fairly simple
   to build from repeated constrained Dijkstra, no library strictly needed if
   pursued).
5. **Minimum-weight k-spanning-tree** — open, deferred (niche, low priority).
6. **Steiner tree** — split: plain/directed Steiner tree open (only
   candidate, OGDF, is GPL-2/3 — excluded on licensing grounds); 📦
   prize-collecting Steiner tree would be closed by pcst_fast, not yet
   implemented.
7. **Property-vector KNN** — 📦 mostly would be closed by hnswlib, not yet
   implemented. Filtered KNN's NN-descent-specific internals
   (`maxIterations`/`randomJoins`/`initialSampler`/`perturbationRate`) would
   remain open regardless — hnswlib's HNSW construction doesn't expose
   equivalent knobs.
8. **K-Means clustering over node property vectors** — open, deferred (best
   options, mlpack/dlib, pull in more than this minimal set wanted).
9. **HDBSCAN over node property vectors** — open, deferred (same
   vector-clustering bucket as K-Means).
10. **SLLPA (overlapping community detection)** — open, deferred (no
    credible maintained library found at all).
11. **K-1 Coloring** — 📦 would be closed by Boost Graph Library
    (`sequential_vertex_coloring`), not yet implemented.
12. **Approximate Maximum k-cut** — open, deferred (only viable option,
    OR-Tools, is too heavy a dependency for this feature).
13. **CELF / influence maximization** — open, deferred (no credible
    maintained library found at all).
14. **GraphSAGE** — out of scope, not included (needs both a GNN library and
    a model-catalog concept beyond age_gds's design).

## Summary of remaining gaps

Ranked by (a) how often the parameter is asked for in practice, (b) whether
it's a permanent NetworKit-side limitation vs. gated on an unimplemented
external-library decision:

1. **`knn_stream` / Filtered KNN** — still conceptually mismatched
   (topology-Jaccard vs. Neo4j's property-vector KNN); the fix (hnswlib) is
   decided but not implemented.
2. **`hits_stream`** — not real HITS (fidelity, not config); the fix (Eigen)
   is decided but not implemented.
3. **`seedProperty`** across `louvain_stream`/`leiden_stream`/
   `labelPropagation_stream`/`wcc_stream` — permanent NetworKit-side gaps
   (no "start from partition" constructor, or UB when one exists).
4. **`sourceNodes`/personalized bias** on `pageRank_stream`/
   `eigenvector_stream`/`articleRank_stream`, and **`maxIterations`** as a
   real parameter on the same three — permanent NetworKit-side gaps (no
   teleport-biasing mechanism; no iteration-cap setter).
5. **FastRP, GraphSAGE** — no age_gds equivalent at all; FastRP is gated on
   Eigen (decided, not implemented), GraphSAGE is out of scope entirely.
6. ~~**`bfs_stream`'s result shape**~~ — **closed.** The SQL function keeps
   its one-row-per-node shape; a new Cypher-callable overload (see
   [Plan: Cypher-Callable Interface](implemented-plans/cypher-callable-interface.md))
   matches Neo4j's single-row/`nodeIds`-list shape.
7. **`node2vec_stream`'s `negativeSamplingRate`** — permanent NetworKit-side
   gap (hardcoded internally).
8. **`direction` on the single-pair link-prediction functions** — permanent
   NetworKit-side gap (`LinkPredictor` rejects directed graphs outright).
9. **Whole missing families** (Yen's, k-spanning-tree, plain Steiner tree,
   K-1 Coloring, K-Means, HDBSCAN, SLLPA, approximate max-k-cut, CELF,
   delta-stepping) — see §7/§8 for per-item status; several are gated on
   external-library adoption decisions not yet executed, others have no
   viable library at all.
