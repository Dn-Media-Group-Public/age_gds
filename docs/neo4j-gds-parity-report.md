# age_gds vs. Neo4j GDS: parameter & functionality gap report

Generated by directly fetching `https://neo4j.com/docs/graph-data-science/current/algorithms/*`
with a real Chrome user agent via Playwright (the site 403s generic HTTP
clients/WebFetch), and diffing the documented config parameters and result
columns against `docs/api.md`. All Neo4j defaults/params below were read
directly off the live doc pages, not inferred.

Every bullet: **what we have** → **what Neo4j GDS has** → **gap**.

---

## 1. Centrality

### `pageRank_stream` / `pageRank_stats` / `pageRank_write`
```sql
age_gds.pageRank_stream(graph_name, damping_factor, max_iterations, tolerance, config, age_graph, node_query, edge_query)
```
Neo4j `gds.pageRank.stream(graphName, configuration)`:
- `dampingFactor` Float, default `0.85` — **have**
- `maxIterations` Integer, default `20` — **have**
- `tolerance` Float, default `0.0000001` (ours: `1e-7`) — **have**
- `relationshipWeightProperty` String, default `null` — **missing**
- `sourceNodes` `Node/Number or List or List of pairs as lists`, default `[]` — **missing** (personalized/biased PageRank; pairs form lets each source carry its own teleport bias)
- `scaler` `String or Map`, default `None` (`None|MinMax|Max|Mean|Log|StdScore`) — **missing**

### `betweenness_stream`
```sql
age_gds.betweenness_stream(graph_name, age_graph, node_query, edge_query)
```
Neo4j `gds.betweenness.stream`:
- `samplingSize` Integer, default = node count — **missing** (enables approximate betweenness; without it, large graphs are impractical since ours always runs exact `O(VE)`)
- `samplingSeed` Integer, default `null` — **missing**
- `relationshipWeightProperty` String, default `null` — **missing**

### `closeness_stream`
```sql
age_gds.closeness_stream(graph_name, age_graph, node_query, edge_query)
```
Neo4j `gds.closeness.stream`:
- `useWassermanFaust` Boolean, default `false` — **missing** (toggles the improved normalization formula; we hardcode NetworKit's `GENERALIZED` variant with no equivalent switch)

### `harmonicCentrality_stream`
```sql
age_gds.harmonicCentrality_stream(graph_name, age_graph, node_query, edge_query)
```
Neo4j `gds.closeness.harmonic.stream`: no algorithm-specific config beyond the standard graph-filter/concurrency set. **No gap.**

### `degree_stream`
```sql

```

- `orientation` String, default `NATURAL` (`NATURAL|REVERSE|UNDIRECTED`) — **missing** (in-degree vs out-degree vs both; we hardcode undirected-style summed degree)
- `relationshipWeightProperty` String, default `null` — **missing** (weighted degree)

### `eigenvector_stream`
```sql
age_gds.eigenvector_stream(graph_name, age_graph, node_query, edge_query)
```
Neo4j `gds.eigenvector.stream`:
- `maxIterations` Integer, default `20` — **missing**
- `tolerance` Float, default `0.0000001` — **missing**
- `relationshipWeightProperty` String, default `null` — **missing**
- `sourceNodes` `List or Node or Number`, default `[]` — **missing** (personalized eigenvector centrality)
- `scaler` `String or Map`, default `None` — **missing**

### `hits_stream`
```sql
age_gds.hits_stream(graph_name, age_graph, node_query, edge_query)
RETURNS TABLE("nodeId" bigint, auth float8, hub float8)
```
Neo4j `gds.hits.stream`:
- `hitsIterations` Integer, default `20` (run as `hitsIterations * 4` Pregel supersteps) — **missing param, and missing the algorithm itself**
- `authProperty` String, default `"auth"` — n/a (property-name config, not applicable to our stream shape)
- `hubProperty` String, default `"hub"` — n/a
- **Fidelity gap, not just params:** Neo4j's HITS is genuine Kleinberg HITS (distinct auth/hub via power iteration on `A^T A` / `A A^T`). Ours returns the same `NetworKit::EigenvectorCentrality` score for both `auth` and `hub` columns — this is a documented substitution, not real HITS.

### `articleRank_stream`

- `dampingFactor` Float, default `0.85` — **have (as constant), missing as parameter**
- `maxIterations` Integer, default `20` — **have (as constant), missing as parameter**
- `tolerance` Float, default `0.0000001` (ours constant is `1e-6`, a different default) — **have (as constant, wrong default), missing as parameter**
- `relationshipWeightProperty` String, default `null` — **missing**
- `sourceNodes` `Node/Number or List or List of pairs as lists`, default `[]` — **missing**
- `scaler` `String or Map`, default `None` — **missing**

### `articulationPoints_stream`
```sql
age_gds.articulationPoints_stream(graph_name, age_graph, node_query, edge_query)
```
Neo4j `gds.articulationPoints.stream` has only the standard graph-filter/concurrency config (concurrency pinned to 1, single-threaded). **No gap.** Neo4j's result additionally includes `resultingComponents` (`{count, min, max}` — sizes of components formed if this node were removed); ours returns bare `nodeId`. Minor result-shape gap, not a config gap.

## 3. Path-finding

### `bfs_stream`
```sql
age_gds.bfs_stream(graph_name, source_node, age_graph, node_query, edge_query)
RETURNS TABLE("nodeId" bigint, distance float8)
```
Neo4j `gds.bfs.stream` config:
- `sourceNode` Integer, required — **have**
- `targetNodes` List of Integer, default `[]` — **missing** (traversal terminates early once any target is visited)
- `maxDepth` Integer, default `-1` (unlimited) — **confirmed missing, as suspected**

**Result shape mismatch:** Neo4j's stream result is `sourceNode, nodeIds, path` — a **single row** containing the ordered list of visited node ids and a `Path` object. Ours emits **one row per node** with a `distance` column. This is a bigger structural difference than the missing `maxDepth` parameter alone; a maxDepth port should decide whether to keep the current per-node/distance shape or move toward Neo4j's single-row/ordered-list shape.

### `dfs_stream`
```sql
age_gds.dfs_stream(graph_name, source_node, age_graph, node_query, edge_query)
RETURNS TABLE("nodeId" bigint, depth int)
```
Neo4j `gds.dfs.stream` config:
- `sourceNode` Integer, required — **have**
- `targetNodes` List of Integer, default `[]` — **missing**
- `maxDepth` Integer, default `-1` — **missing**

### `shortestPath_dijkstra_stream`
```sql
age_gds.shortestPath_dijkstra_stream(graph_name, source_node, age_graph, node_query, edge_query)
RETURNS TABLE("nodeId" bigint, distance float8)
```
Neo4j splits this into two distinct procedures:
- `gds.shortestPath.dijkstra.stream` (**source-target**): config `sourceNode` (required), `targetNode`/`targetNodes` (required, `Integer or List of Integer`), `relationshipWeightProperty`. Result: `index, sourceNode, targetNode, totalCost, nodeIds, costs, path` — returns the actual path(s), not just a distance.
- `gds.allShortestPaths.dijkstra.stream` (**single-source-to-all**, the true counterpart of ours): config `sourceNode` (required), `relationshipWeightProperty` (default `null`, **missing in ours**). Result: `index, sourceNode, targetNode, totalCost, nodeIds, costs, path` — **also returns the full path per target**, not distance-only.

Gaps: (1) no `relationshipWeightProperty` per-call override — ours relies solely on the graph's `weighted` flag set at projection time; (2) no path output at all, only distance; (3) no source-target single-pair mode (`targetNode`/`targetNodes`) — this is arguably a separate, commonly-requested function we don't have at all.

### `deltaStepping_stream`
```sql
age_gds.deltaStepping_stream(graph_name, source_node, age_graph, node_query, edge_query)
```
**Substitution:** runs plain `NetworKit::Dijkstra`, not delta-stepping. Neo4j `gds.allShortestPaths.delta.stream` config adds:
- `delta` Float — **missing**, and structurally can't be added without an actual delta-stepping implementation (NetworKit has none — per CLAUDE.md, "never implement a graph algorithm from scratch," so this would need to stay a documented substitution, or be dropped).

### `bellmanFord_stream`
```sql
age_gds.bellmanFord_stream(graph_name, source_node, age_graph, node_query, edge_query)
```
**Substitution:** runs `NetworKit::Dijkstra`; doc says negative weights unsupported. Neo4j `gds.bellmanFord.stream`:
- `sourceNode`, `relationshipWeightProperty` — same base shape
- Result includes `isNegativeCycle` Boolean per path, and stats mode reports `containsNegativeCycle` Boolean — **missing**: ours has no negative-cycle detection or reporting at all, it just documents the limitation.

### `randomWalk_stream`
```sql
age_gds.randomWalk_stream(graph_name, source_node, walk_length DEFAULT 10, age_graph, node_query, edge_query)
RETURNS TABLE("nodeId" bigint)
```
Neo4j `gds.randomWalk.stream` config:
- `sourceNodes` **List of Integer**, default = **all nodes in the graph** — **different design**: ours takes one `source_node` (must be non-null); Neo4j defaults to running walks from every node if unspecified, and accepts a list for multi-source.
- `walkLength` Integer, default **`80`** (ours defaults to `10`) — **different default, worth reconciling**
- `walksPerNode` Integer, default `10` — **missing** (ours only ever does 1 walk per call)
- `inOutFactor` Float, default `1.0` (a.k.a. `q`, DFS/BFS bias) — **missing**
- `returnFactor` Float, default `1.0` (a.k.a. `p`, revisit bias) — **missing**
- `relationshipWeightProperty` — **missing**

Note: node2vec's walk generation already implements return/in-out bias via NetworKit's Node2Vec walker; `randomWalk_stream` could potentially delegate similarly instead of the current `Aux::Random::choice` uniform-walk substitution, to pick up `returnFactor`/`inOutFactor` for free.

### `spanningTree_stream`
```sql
age_gds.spanningTree_stream(graph_name, age_graph, node_query, edge_query)
RETURNS TABLE(src bigint, dst bigint, cost float8)
```
Neo4j `gds.spanningTree.stream` config:
- `sourceNode` Integer, **required** — **missing entirely**: ours has no `source_node` parameter, so it can't express Neo4j's root-anchored semantics; NetworKit's `SpanningForest` builds a forest independent of any root.
- `relationshipWeightProperty` — **missing**
- `objective` String, default `'minimum'` — **missing** (Neo4j also exposes a separate `gds.beta.maximumWeightSpanningTree` for the maximum-weight variant; our docs don't state which objective `NetworKit::SpanningForest` optimizes for, if any — worth clarifying since `SpanningForest` is unweighted/topological, not a MST algorithm at all).

### `allShortestPaths_stream`
```sql
age_gds.allShortestPaths_stream(graph_name, age_graph, node_query, edge_query)
RETURNS TABLE("sourceNodeId" bigint, "targetNodeId" bigint, distance float8)
```
Neo4j `gds.allShortestPaths.stream` (true APSP, distinct from the single-source `allShortestPaths.dijkstra`/`.delta` procedures despite the similar name) matches our shape exactly: `sourceNodeId, targetNodeId, distance`. Config adds:
- `relationshipWeightProperty` String, default `null` — **missing**

**No structural gap** — good match. Just the missing per-call weight-property override, consistent with the rest of the report.

### `maxFlow_stats`
```sql
age_gds.maxFlow_stats(graph_name, source_node, target_node, age_graph, node_query, edge_query)
RETURNS TABLE(flow float8, "computeMillis" bigint)
```
Neo4j `gds.maxFlow.stream`/`.stats` config:
- `capacityProperty` String, **required** — **missing**: Neo4j always reads capacity from an explicit relationship property (not the generic edge weight); ours relies on the graph's weight.
- `sourceNodes` `List of Nodes or Integers or Integer`, **required** — **missing**: multi-source
- `targetNodes` `List of Nodes or Integers or Integer`, **required** — **missing**: multi-sink
- `nodeCapacityProperty` String, default `n/a`, optional — **missing**: node-capacity constraints (vertex splitting), not just edge capacity

Neo4j also has a distinct **`gds.minCostMaxFlow`** procedure we have no equivalent of at all (see §6).

## 4. Similarity

### `nodeSimilarity_stream`
```sql
age_gds.nodeSimilarity_stream(graph_name, age_graph, node_query, edge_query)
RETURNS TABLE(node1 bigint, node2 bigint, similarity float8)
```
Neo4j `gds.nodeSimilarity.stream` config — **all missing**:
- `similarityCutoff` Float, default `1e-42` (filters out ~zero scores)
- `degreeCutoff` Integer, default `1` (skip nodes below this degree)
- `topK` Integer, default `10` (top-K neighbors per node — Neo4j does **not** default to full pairwise output)
- `topN` Integer, default `0` (global cutoff on total result rows, 0 = unlimited)
- `relationshipWeightProperty` String, default `null`

Ours always computes the full `O(n²)` unordered pairwise Jaccard with no bound — a strictly more expensive, unbounded variant of Neo4j's default top-K-per-node behavior. This is the top scalability concern in the whole report for any graph beyond toy size.

### `knn_stream`
```sql
age_gds.knn_stream(graph_name, top_k DEFAULT 5, age_graph, node_query, edge_query)
RETURNS TABLE("sourceNodeId" bigint, "targetNodeId" bigint, similarity float8, rank int)
```
Neo4j `gds.knn.stream` config:
- `nodeProperties` `String or Map or List of Strings/Maps`, **required** — **conceptual mismatch**: Neo4j KNN computes similarity over **node property vectors** (numeric/embedding features), not graph topology. Ours computes Jaccard over neighbor sets, same as `nodeSimilarity`, making our `knn_stream` effectively a differently-parameterized `nodeSimilarity_stream` rather than true KNN.
- `topK` Integer, default `10` (ours defaults to `5`) — **different default**
- `sampleRate` Float, default `0.5` — **missing**
- `deltaThreshold` Float, default `0.001` — **missing**
- `randomSeed` — **missing**
- `similarityCutoff` — **missing**

Neo4j also has a separate `gds.knn.filtered.stream` (source/target node filtering) we have no equivalent of.

## 5. Link prediction

### `linkprediction_adamicAdar_stream` / `commonNeighbors_stream` / `preferentialAttachment_stream` / `resourceAllocation_stream`
```sql
age_gds.linkprediction_adamicAdar_stream(graph_name, age_graph, node_query, edge_query)
RETURNS TABLE(node1 bigint, node2 bigint, score float8)
```
Neo4j's equivalents are **scalar Cypher functions**, not streaming procedures. All four (`adamicAdar`, `commonNeighbors`, `preferentialAttachment`, `resourceAllocation`) were fetched directly and confirmed to share the **exact same parameter signature**:
```
gds.alpha.linkprediction.<name>(node1, node2, { relationshipQuery, direction })
```
| Name | Type | Default | Optional |
|---|---|---|---|
| `node1` | Node | `null` | no |
| `node2` | Node | `null` | no |
| `relationshipQuery` | String | `null` | yes |
| `direction` | String | `BOTH` (`OUTGOING\|INCOMING\|BOTH`) | yes |

Result: a single `score` Float. Called for one pair at a time.

**Structural mismatch:** ours uses NetworKit's `runAll()` and streams **every unconnected node pair** (`~node_count²/2` rows) for a full-graph score matrix. This is a fundamentally different, far more expensive usage pattern than Neo4j's per-pair spot-check design. Also missing: `direction` (OUTGOING/INCOMING/BOTH) and `relationshipQuery` (edge-type filtering) — neither is expressible in our current signature. Worth an explicit design note in `docs/api.md` calling out that this is a deliberate divergence, or reconsidering the "stream all pairs" approach for large graphs.

## Summary of highest-priority gaps

Ranked by (a) how often the parameter is asked for in practice, (b) scalability impact of not having it:

1. **`louvain_stream`** — zero config exposed vs. 7 Neo4j params (`maxLevels`, `maxIterations`, `tolerance`, `includeIntermediateCommunities`, `seedProperty`, `consecutiveIds`, `relationshipWeightProperty`).
2. **`nodeSimilarity_stream`** — no `topK`/`topN`/cutoffs; always O(n²), unbounded.
3. **`betweenness_stream`** — no `samplingSize`; always exact, unusable on large graphs.
4. **`bfs_stream`/`dfs_stream`** — no `maxDepth`/`targetNodes`; always full traversal.
5. **`degree_stream`** — no `orientation`; can't get in-degree vs out-degree.
6. **`hits_stream`** — not real HITS (fidelity, not config).
7. **`maxFlow_stats`** — single source/sink only, edge-weight-as-capacity only.
8. **`leiden_stream` / `labelPropagation_stream` / `wcc_stream`** — same missing-config pattern as Louvain.
9. **`knn_stream`** — conceptually mismatched (topology-Jaccard vs. Neo4j's property-vector KNN).
10. **Link-prediction family** — runAll-streaming vs. Neo4j's single-pair scalar-function design.
